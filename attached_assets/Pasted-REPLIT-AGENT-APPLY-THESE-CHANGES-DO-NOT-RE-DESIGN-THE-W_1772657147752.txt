A) CRITICAL BUG FIX — CONTAINER TYPE MUST NOT AUTO-UPGRADE
========================================================
Problem:
- User selects 40’ HQ, but when cargo doesn’t fit, the app “upgrades” to 45’ HQ and reports/visualizes that.
- This must NOT happen. The selected container must always remain the one used for packing/calculation.
- If items don’t fit, show a clear message + optional “Try bigger container” suggestion button, but DO NOT silently switch containers.

Where it happens:
- In handleCalculate() there’s an “upgrade loop” using UPGRADE_MAP that mutates useContainer.
- I saw logic like:
  - nextId = UPGRADE_MAP[containerId]
  - while (...) { tryRes = packBoxes(... nextContainer) ... useContainer = nextContainer ... upgraded=true ... }

Required change:
1) Remove/disable automatic upgrade behavior by default.
2) Keep “suggestion” logic only as a recommendation UI message:
   - Keep the original result from the user-selected container.
   - If unplaced.length > 0, compute a suggested container (optional) BUT DO NOT apply it.
3) Update the UI message:
   - Instead of “automatically upgraded”, show:
     “Some items don’t fit in 40' HQ. Suggested: 45' HQ (click to try).”
   - Provide a button: “Try suggested container”
     - This button re-runs calculation with that suggested container and ONLY then updates selection (explicit user action).

Implementation steps:
- In handleCalculate:
  - Always set `useContainer` = selected container (or custom).
  - Run `res = packBoxes(validItems, useContainer)`
  - If res.unplaced.length > 0:
    - Compute `suggestedContainer` by iterating upgrade map (same loop), but store ONLY the best suggestion in a variable.
    - Do not overwrite useContainer/res automatically.
  - Store into state:
    - `fitStatus: "fit" | "not_fit"`
    - `suggestedContainer?: ContainerSpec`
    - `unplacedItems?: Item[]`
- Add a small UI panel under “Calculate Loading Plan” results:
  - If not_fit:
    - Show red/amber alert with count of unplaced items and suggested container name.
    - Button: “Try {suggestedContainer.name}”
      - On click: setSelectedContainerId(suggestedContainer.id) AND run calculate again (or call calculate with forced container).

Acceptance criteria:
- If user selects 40’ HQ, result header and 3D viewer MUST still say 40’ HQ even if it doesn’t fit.
- No “automatic upgraded” wording.
- Only changes container if user clicks the explicit “Try suggested container” button.
